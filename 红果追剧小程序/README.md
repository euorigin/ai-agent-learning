# 红果追剧助手 · 微信小程序

一个「短剧订阅 + 更新提醒 + 个性化推荐」小程序。

用户可以添加在追的短剧，剧集更新时会收到应用内提醒；首页会根据看过/在追的内容，
推荐热播榜和「猜你喜欢」，每条推荐都带可解释理由（如"因为你追了《XXX》"）。

---

## 功能一览

| 页面 | 能力 |
| --- | --- |
| 推荐（首页） | 品牌头 + 热播榜横滚 + 猜你喜欢（带推荐理由） |
| 发现 | 关键词搜索（剧名/标签/演员）+ 分类筛选 + 一键追剧 |
| 追剧 | 订阅列表、观看进度、`有更新` 标记、立即检查更新、演示用模拟更新 |
| 消息 | 应用内消息中心，未读高亮、全部已读、清空、点击跳详情 |
| 详情 | 剧集信息、选集（新集高亮）、同类推荐、底部常驻操作栏 |

底部 TabBar 为自定义组件，`消息` 带未读数角标、`追剧` 带更新小圆点。

## 关于数据源（重点）

**红果短剧没有官方公开 API**，且微信小程序不允许直接调用其他 App 的私有接口。
因此本项目把数据源做成**可插拔适配层**，而不是写死某个接口：

```
页面 ──> dramaService ──┬──> realAdapter  （真实接口，优先）
                        └──> mockAdapter  （种子数据，兜底）
```

- **成功**：用真实数据，首页标记显示 `● 实时数据`
- **失败/为空**：静默回落到本地种子库，标记显示 `● 本地演示数据`，界面永远有内容
- **熔断**：真实源连续失败 `realFailThreshold` 次后，本次会话不再尝试它，
  避免"每个请求都白等 5 秒超时"。想手动恢复：`dramaService.resetCircuit()`

### 切换模式

编辑 `miniprogram/config/index.js`：

```js
mode: 'auto'   // 推荐：真实源优先，失败自动回落
mode: 'real'   // 只走真实源（联调线上接口时用）
mode: 'mock'   // 只走本地数据（答辩/断网演示最稳）
```

### 接入你自己的真实数据

`realAdapter.js` 已经把字段映射集中在一处，改这一个文件即可：

1. 改 `config.api.base` 为你自己的接口地址
2. 若返回结构不同，调整 `pickArray()`（取列表）和 `normalizeDrama()`（字段映射）
3. 让接口返回项目统一结构（见 `data/seed.js` 顶部注释）即可，上层业务无需改动
4. **发布前**：在微信公众平台「开发管理 → 服务器域名」把域名加入 `request 合法域名`
   （必须 HTTPS）。更推荐的做法是自建一层后端代理，便于签名、缓存、限流与合规

> 调研到的可用方向：第三方聚合接口（如示例中的 `api-v2.cenguigui.cn`）、
> Apify 的 `hongguo-recommend-feed` / `hongguo-search` actor（付费）。
> 注意：这类接口均为第三方，存在稳定性与合规风险，仅建议用于学习研究。

## 推荐算法

「猜你喜欢」= 对候选剧库逐个打分排序，公式：

```
score = 标签相似度 × tagWeight       (默认 0.6)
      + 归一化热度 × heatWeight      (默认 0.3)
      + 同分类加成 × categoryWeight  (默认 0.1)

标签相似度 = Σ(命中标签在用户画像中的权重) / 画像标签总数
```

- **用户画像**：把「我的追剧」里每部剧的标签聚合计数，出现次数越多代表口味越核心
- **可解释理由**：找出与候选剧标签重合最多的那部已追剧，生成"因为你追了《XXX》"
- **冷启动**（还没追任何剧）：退化为纯热度排序，理由显示"当前热播"
- 权重可在 `config.recommend` 调整

详情页的「同类推荐」复用了同一套引擎：把当前剧自己当作临时画像传进去。

## 更新提醒链路

```
app.onLaunch / onShow
      └─> updateService.checkUpdates()
            └─ 对每部订阅剧：拉最新集数 vs 本地已知集数
                  └─ 有增长 → 更新订阅记录 → 写入消息中心 → TabBar 角标点亮
```

- 进详情页会调用 `updateService.markSeen()`，标记"已看到最新集"
- 同一部剧未读的更新消息会被**合并覆盖**，反复打开小程序不会刷屏

### 为什么放在前台触发？

小程序没有后台常驻定时任务。真实产品应该把这一步搬到**服务端**：

1. 服务端定时任务（如每天定时）拉取订阅剧集的最新集数
2. 发现更新 → 调用微信「订阅消息」接口推送给用户（需在小程序内引导用户授权，且模板需审核）
3. 服务端同时把消息写库，小程序启动时拉取历史消息

本项目已经把更新检测收敛成一个纯函数式入口（`updateService.checkUpdates()`），
将来挪到服务端或云函数时，逻辑可以整体复用。

## 已知限制

- 数据源为第三方接口，可能失效/变更；核心逻辑用种子数据保证可演示
- 订阅关系与消息存在**本地存储**，换设备不同步（真实产品需落服务端）
- 未接入真实视频播放，详情页选集为占位交互（真实产品用
  `wx.navigateToMiniProgram` 跳转红果小程序）
- 未接入微信订阅消息推送，仅有应用内消息中心
